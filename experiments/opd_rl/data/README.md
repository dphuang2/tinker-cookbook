# opd-rl raw data

All raw artifacts from the autoresearch loop. Reproduces every figure and every
number in `../findings.md`.

## Layout

```
data/
├── teacher_ref.json                # iter03: teacher zero-shot eval (64 problems)
├── forgetting-*.json               # iter08: 16-prompt IF rubric, one per checkpoint
├── forgetting2-*.json              # iter11: 26-prompt (harder) IF rubric
└── iter<NN>/
    ├── config.json                 # full chz config of the run
    ├── metrics.jsonl               # per-step aggregate metrics (one JSON line/step)
    └── rollouts.jsonl              # one JSON line per trajectory (RL/OPD-RL runs only)
```

Iter map:

| iter | variant                                | rollouts? |
|------|----------------------------------------|-----------|
| 04   | OPD only (30 steps)                    | no¹       |
| 05   | RL matched-hp (collapsed)              | yes       |
| 06   | RL tuned (30 steps)                    | yes       |
| 07   | OPD-then-RL (30 steps)                 | yes       |
| 08   | OPD-then-RL seed=2 (30 steps)          | yes       |
| 09   | RL tuned seed=2 (30 steps)             | yes       |
| 10   | OPD-then-RL 60 steps                   | yes       |
| 12   | RL tuned 60 steps (currently running)  | yes (pending) |

¹ The OPD trainer (`tinker_cookbook.distillation.train_on_policy`) does not emit
per-iteration logtrees, only metrics. For iter04 you can re-sample from the
saved checkpoint `tinker://43426da0-…/sampler_weights/final` to inspect
trajectories.

## metrics.jsonl schema

Each line is one training step's aggregate metrics. Keys of interest:

- `progress/batch` — step index (0-indexed)
- `env/all/reward/total` — mean trajectory reward across the batch
- `env/all/correct` — fraction of trajectories with a correct expression
- `env/all/format` — fraction with a syntactically valid `<answer>…</answer>` tag
- `env/all/by_group/frac_all_bad` — fraction of *groups* where every member failed
  (a useful proxy for "RL has no learning signal here")
- `env/all/by_group/frac_all_good` — fraction of groups where every member succeeded
- `teacher_kl` — mean per-token reverse KL student↔teacher (OPD runs only)
- `optim/entropy`, `optim/lr` — optimizer stats

The full key list per row is large; these are the ones used in `findings.md`.

## rollouts.jsonl schema

Generated by `experiments/opd_rl/extract_rollouts.py` from each RL run's raw
`iteration_*/train_logtree.json`. Each line is one trajectory:

```json
{
  "iter": 0,                                    // training step
  "traj_idx": 0,                                // index within the batch at that step
  "prompt": "Using each of the numbers …",      // the env's user message
  "response": "We are given … <answer>…</answer>", // student's completion
  "reward": 0.0                                 // final trajectory reward
}
```

Trajectories per run vary with `groups_per_batch × group_size × steps`. For the
30-step runs that's 16 × 4 × 30 / sampling = ~960; iter10 (60 steps, group_size=8)
has ~1920.

## forgetting-*.json schema

```json
{
  "label": "opd_then_rl",
  "model": "Qwen/Qwen3-4B-Instruct-2507",
  "checkpoint": "tinker://…/sampler_weights/final",
  "n_prompts": 16,
  "forgetting_score": 0.9125,
  "per_prompt": [
    {"prompt": "…", "score": 1.0, "reason": "words=1", "resp": "Paris"},
    …
  ]
}
```

`per_prompt` is the audit trail — every response and the rule the scorer
applied. `forgetting-*.json` is the iter08 16-prompt rubric; `forgetting2-*.json`
is the iter11 26-prompt (harder) rubric. Both use rule-based scoring; no LLM
judge.

## teacher_ref.json schema

Output of `eval_teacher_ref.py`. Mean reward / correct / format across 64
fresh Countdown problems sampled by the teacher with `T=1.0`, group_size=1.
Used as the anchor for `vs_teacher_gap` in `results.tsv`.

## Reproducing figures

```bash
uv run python -m experiments.opd_rl.make_figures
```

reads everything under `data/` and rewrites every PNG under `../figures/`. No
external state.
